Support

Most problems come down to one of four things: the two devices aren't on the same network, the host isn't running, macOS hasn't granted a permission, or a safety switch is doing its job. Here's how to tell which one you've hit.

Quickest route: email aryasoftechco@gmail.com with what you tapped and what the status line at the top of the app said. The status line reports every result — it's usually the whole diagnosis. Bug reports and feature requests are also welcome on GitHub Issues.

Setting up

  1. Run the desktop host on your computer (see Download). It lives in the menu bar / tray and shows a Pair a phone window with a QR code.
  2. Open DeskAssist on your phone and scan that QR. Both devices must be on the same Wi-Fi. No camera to hand? Click Copy pairing data on the computer and use Enter pairing data manually on the phone.
  3. Tap a tile. The default deck launches Safari, VS Code, Finder and friends. Tap Edit to make it yours.

No computer nearby? Tap Explore the demo instead on the first screen — the entire app runs against a simulated Mac so you can try everything first.

Troubleshooting

The QR code won't scan, or pairing fails

Make sure the phone and the computer are on the same Wi-Fi network — guest networks and hotel/office Wi-Fi often isolate devices from each other ("client isolation"), which blocks the connection even when both show full bars.

If the scanner never reacts, it's probably reading a different QR nearby, or camera access is off (iOS Settings → DeskAssist → Camera). The manual route always works: Copy pairing data on the computer, Enter pairing data manually on the phone.

"Can't reach host" after it used to work

The host app has to be running on the computer — look for its icon in the menu bar (macOS) or tray (Windows). If the computer went to sleep, changed networks, or got a new IP address from the router, unpair on the phone (Edit → Unpair) and scan a fresh QR.

A firewall prompt you dismissed can also block it: allow incoming connections for the host app in your firewall settings.

Keyboard shortcuts and text typing don't work (macOS)

Sending keystrokes needs macOS Accessibility permission. Open System Settings → Privacy & Security → Accessibility and switch the host app on. App launching and URLs work without it — only Shortcut and Text tiles need it.

Shell tiles say they're blocked

That's deliberate. Shell commands are arbitrary code execution, so they ship disabled by default and must be switched on in the host's tray menu on the computer itself — a paired phone can never enable them remotely. There's also an optional allowlist so only exact commands you approve can run.

A tile presses but nothing happens

Check the status line at the top of the deck — every press reports success or the exact error. For App tiles the name must match the real application name exactly (e.g. Visual Studio Code, not VS Code). The Apps screen (🖥 button) lists the names the computer actually reports — pinning from there always gets it right.

How do I start over?

Edit → Unpair disconnects from the computer and returns to the pairing screen; your deck layout stays. Reset page (in edit mode) restores a page's default tiles. Deleting the app removes everything it ever stored — there is no account and no server-side copy.

Frequently asked questions

Is DeskAssist really free?

Yes — everything, with no in-app purchases, subscriptions, accounts or ads. The code is open source under the MIT licence.

Does it work away from home, over the internet?

No, by design. The phone talks directly to your computer over your own network — no relay server exists, which is a big part of why it's safe to give an app the ability to type into your windows.

What platforms are supported?

The phone app runs on iOS and Android. The desktop host runs on macOS and Windows: app launching, URLs, keyboard shortcuts and text typing work on both; shortcuts/text use AppleScript on macOS and SendKeys on Windows.

Why does the app want camera access?

Solely to scan the pairing QR code. Nothing is recorded, stored or uploaded, and you can skip the camera entirely with manual pairing or the demo. See the Privacy Policy.

Is the connection actually secure?

Pairing performs an X25519 key exchange (the QR carries a public key, never a secret), and every command is sealed with AES-256-GCM with replay protection. Tampered or replayed messages are rejected. The full design is documented in the repository.
